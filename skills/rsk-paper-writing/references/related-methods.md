# 相关工作与方法

依据教程 12《如何写论文-Related Works》和 13《如何写论文-Methods》。

## 相关工作：形成技术定位

引言用于建立问题动机；相关工作用于说明技术谱系与本文位置。以方向、问题、设计或假设分类，每组采用“归类 -> 综合 -> 代表工作 -> 关系或局限”的结构，不按论文逐篇写流水账。

先说明同类方法共同的目标或机制，再给代表文献与有依据的差异。批评应限定到条件，不笼统宣称全部旧方法无效。本文关系可能是扩展、互补、对比、统一或重新评估，不必全部写成替代与胜出。

对比表选择领域认可、与当前问题有关的维度；不存在某功能与作者没有报告该功能应区别标记。不能发明维度或选择性省略竞争优势来制造全面优越。

## 方法：使设计可理解和复现

通常采用总览 -> 问题与符号 -> 模块 -> 训练或优化 -> 推理或部署的功能顺序。非机器学习工作可改为实验对象、过程与测量；保留学科必要的信息，不添加没有的训练步骤。

总览与主图协同说明整体输入、流向、模块和输出。问题定义包含输入、输出、目标和必要符号，让读者先理解任务再读细节。

模块围绕六件事展开：解决什么问题、接收什么、怎样处理、产生什么、为什么需要、依赖什么假设。与最近邻的差异要具体；若去掉该模块，哪项能力预计受影响？实测的影响放到实验并给定位。

公式先说明动机，公式后定义所有新符号，再解释其作用与直观意义。统一符号，避免同一字母承担不相容的含义；减少不必要下标或装饰性公式。量纲、索引与定义范围按领域检查。

训练、优化和推理部分清楚交代目标、过程与使用条件。正文负责解释逻辑，伪代码负责精确呈现流程；不能让算法框替代全部说明。超参数和复现细节按投稿篇幅分配至正文或附录。

## 修改时的边界

改变文字不能改变算法、实验过程或公式含义。缺少过程细节时提出缺口，不从常见做法猜成事实。新增机制解释标注为假设，除非已有分析或证据支持。
