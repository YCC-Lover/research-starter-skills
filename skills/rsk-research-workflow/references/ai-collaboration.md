# 可验证的 AI 科研协作

依据教程 19《AI 辅助科研的一些 Tips》。原文以 Claude 与 macOS 为操作环境；以下提炼其协作原则，不把命令、权限和快捷键迁移到 Codex。

## 任务与上下文

尽量让一个工作上下文围绕明确方向。先对齐关键材料、目标和影响实现的细节；细节不影响结果时可说明合理假设后推进，不要求每件小事反复确认。

设定可观察的交付和验收依据，例如真实数据、编译结果、测试或专家明确标准。开始复杂实现前建立适当的 smoke test，完成后看实际文件与验证结果，不只看漂亮总结。

项目约定保存在用户指定的持久文件中；临时对话不等同于持久记忆。原文关于退出后上下文消失的说法不是所有产品的数据保留政策。使用 Codex 的项目指令需遵循实际机制，不擅自创建或改写 CLAUDE.md。

## 检索与独立检查

先获得相关文献再做大量阅读。工具与权限允许时可拆分独立阅读或验证任务，并为每个任务限定输入、证据格式和范围；不声称不存在的子代理已经检查。

不同角度重查方法、代码和论文细节可以发现遗漏。检查真实 diff 与结果，对照用户要求。发现错误时进行有界修复，不将原文的持续重启建议变成无限循环；重复外部阻塞时应说明问题并等待必要输入。

分支与检查点用于比较方案和理解难点，不默认允许回滚用户改动。创建提交、撤销变更与清理仍按实际请求和当前指令执行。

## 实验日志与自动化

先由用户或现有指标指出 wandb 等平台中的异常，再聚焦时间段、实验 ID 和指标。大日志可拆成有界检查，保留证据路径；不凭模型推断远程凭证或可访问性。

昂贵实验自动化需有实际的启动、停止与配置控制，以及用户要求的完成或失败通知机制。明确预算、停止条件和权限，不因教程提及 hook 就擅自配置服务、持续监控或通知所有进度。

向 AI 解释禁止行为及原因，可以帮助正确决策；禁止规则本身仍由当前用户和环境约束。中间脚本、缓存、预览与测试产物遵循当前用户的存储要求；本仓库 Windows 维护约定使用 D/E 盘工作目录，不要求其他平台创建这些盘符。禁止批量删除，最终文件与持久配置保存在其指定位置。

历史命令索引见 [claude-snapshot.md](claude-snapshot.md)。需要当前 Codex 操作指导时查本地版本及官方资料，而不是推测同名命令等价。
