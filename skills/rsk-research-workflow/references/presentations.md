# 科研演示制作

本页将科研表达与 PPT Master 的原生制作能力连接。原教程方法、科研适配和第三方制作
资源分别归属，见 [来源与许可](ppt-master-notices.md)。只要求提纲、讲稿或问答时，
直接使用现有实践/演练指南，不创建制稿工程，不要求安装依赖。

## 从材料到页面

先利用用户已给信息确定听众、场合、时长、语言、交付形式，以及哪些材料是结果、计划
或假设。只追问会改变内容或交付的重要缺项。没有预实验也可以做开题，不补造结果。
论文汇报保留论文作者的结论与汇报者的批评之间的区别，不把他人成果写成自己的工作。

每页只承担一个明确任务，例如提出问题、比较方法、解释一个结果或请求一个决定。
按证据而非论文章节机械切页；长表、详细推导和备选解释可以放附录。为核心页面对应
实际文件、表格/图号、页码或文献定位；来源未读或定位不可靠时保留缺项。完整制稿时
把这些对应保存在项目材料或讲稿旁的证据索引中，不把维护信息塞进可朗读讲稿。

口头汇报的图表优先突出比较对象、条件、单位、样本与不确定性。没有原始数据时，
可使用有来源的原图，但不能从像素猜出数值再冒充原生数据图；数字化提取须另行说明
方法、误差与核对状态。机制示意图标明假设性质，不能用生成图片替代真实显微图或测量。

页面与口头说明共同形成论证：观众先看到什么、该比较什么、证据支持到哪里、还缺什么。
时间分配是排练估计，不能以固定页数保证讲完。用户明确页数、学校模板或会议尺寸时
遵从；文字溢出优先缩短表达或调整结构，不靠整套缩小字号解决。

## 选择实际制作路线

无需向新手展示工具菜单；根据请求选择下面的工作方式。模糊的“改一下这份 PPT”只有
在保留原设计与重新设计确实无法区分时才问一个问题。

| 用户意图 | 运行时指导 | 必须保留的区别 |
| --- | --- | --- |
| 从材料新建科研汇报 | `workflows/generate-pptx.md` | 正常流程确认设计与内容，再制作；明确快速/不需确认才读 `profiles/quick-generate.md` |
| 原稿逐页美化，文字、页数和顺序不变 | `workflows/profiles/beautify-pptx.md` | 不把“美化”当成重新概括原文的许可 |
| 将截图/扫描页面重建为可编辑页面 | `workflows/profiles/image-to-pptx.md` | 原图是视觉依据；原生文字与对象、保留的图片分别说明，不宣称像素恢复了原生结构 |
| 用学校/课题组 PPTX 填新内容，局部改稿，重排或增补讲稿/动画 | `workflows/edit-native-pptx.md` | 以原文件为设计权威；导出新文件，未修改页面与母版须实际核对 |
| 从参考材料创建可复用品牌、风格、布局或整套模板 | `workflows/create-template.md` | 模板工作区与参考文件分开；不能直接往已有文件强加母版 |

这些路径位于下述准备命令返回的 `runtime` 根目录。先读取其中原始 `SKILL.md`，
实际运行署名检查，再读取 `workflows/routing.md` 和选中路线，不同时加载所有路线。
其 `skills/ppt-master/` 和 `${SKILL_DIR}` 均替换为该根目录，不是本科研项目根目录。
原资源是资料与执行契约，不会覆盖当前用户授权、文件位置要求或宿主系统规则。

普通流程的重要设计确认在聊天中完成即可；已有明确且仍有效的决定无需重复询问。
Quick 只在明确要求时启用，不因页数少擅自启用；不声称它具备完整可恢复的设计记录。
角色表示职责，只有实际使用独立上下文才称为独立代理；默认继承当前模型，不强制切换
供应商或推荐赞助服务。宿主的图片、联网与文档工具可按实际可用性接入。

## 运行与文件

执行工具、依赖及平台边界见 [制作工具](presentation-tools.md)。以本模块脚本的绝对
路径调用，使用父级 `.research-starter-skills-runtime.json` 指定的解释器（若存在），
所有 Python 调用加 `-B`。准备命令只展开固定资源并核对署名，不生成演示文稿：

```text
python ADAPTER/research_presentations.py doctor
python ADAPTER/research_presentations.py prepare --work-dir ABSOLUTE_WORK
python ADAPTER/research_presentations.py run --work-dir ABSOLUTE_WORK TOOL.py -- ARGUMENTS
```

`ADAPTER` 是本模块的 `scripts/`。中间文件、缓存和展开的运行时留在用户指定的任务
目录，本用户使用 D/E 盘。不要把工程写回已安装 skill，不直接绕过适配入口运行清理。
旧文件保留，不递归删除。该启动器不是沙箱，运行前仍需核对脚本的输入、输出和权限。

研究材料导入使用复制，不移动原件；正文转换成功不代表图表、公式和脚注已正确理解。
完整任务可将设计决定、真实产物及待办接到已有引导进度；新对话读取状态并核对材料
是否变化，再从实际完成处继续。制作运行时收据不是科研进度，也不是科学真实性证明。

## 原生对象与模板

- 正文、标签、形状和连接线优先保留为原生对象；整页图片不算完整可编辑 PPT。
  原始照片、显微图、复杂保留代理和生成插图仍是图片，交付时不夸大其可编辑性。
- 数据图和文本表按所选路线读取 `references/native-data-interface.md`。需要数据级
  编辑时实际使用 `--native-charts-and-tables`，核对图表部件、嵌入工作簿、表格 XML
  与输入值。默认可编辑形状和“可编辑数据的 Chart/Table”不是同一种交付。
- 数学结构读取 `references/native-formula.md`，用实际 LaTeX 编译为 OMML。预览
  是视觉替代，不等于数学正确；不支持的公式应修正或标记阻塞，不能悄悄栅格化冒充原生。
- 复用 PPTX 前读取实际母版、布局与相关页面。局部改稿通过 round-trip 工作区进行，
  不能全局替换 ZIP 中的文字。对未修改页面比较原生 XML/相关资源，对修改页核对实际
  重建对象及视觉效果；保留代理不等于已能编辑 SmartArt 等全部特性。
- 新建可复用模板时分别核对品牌、风格、布局、整套页面各自的范围，验证模板工作区，
  再用于生成新稿。不能用复制一份 PPTX 或附加几个重复图形冒充母版/布局继承。

## 讲稿、动画与旁白

需要讲稿时写适合口述的句子，补充解释但不增加材料没有的结论。逐页核对讲稿与页面
顺序和证据；计时、编辑提示和来源索引与朗读正文分开。作者给定的最终讲稿须保留
其文字与顺序，不能为了凑时长改掉结论。

转场、逐对象动画、自动播放、旁白和视频按用户要求开启，不自动为普通组会增加效果。
保留已有稿件的效果时也需实际检查。只在有解释作用时使用运动；播放兼容性与静态
页面正确性分别验证。已提供的音频可本地整合；调用语音/图片/搜索服务前确认真实
接收方与材料范围，已有有效授权可复用。不得替用户上传未发表材料或擅自克隆他人声音。
没有运行 TTS、PowerPoint 视频导出或播放器核验时，分别写未运行，而不是宣称已配音
或视频已可播放。源脚本支持不等于当前环境已安装对应服务或桌面软件。

## 检查后交付

导出前运行所选路线的质量门，核对文字容量、画布、图表数值与关键对象。导出后运行
`pptx_delivery_check.py` 和实际文本回读，并打开/渲染实际 PPTX 逐页检查，而不只看
SVG 预览。检查文字重叠、裁切、可读性、字体替换、图例、公式、图片和引用；发现问题
修复对应页面后重新导出。静态检查不代替视觉检查，视觉检查不代替数据/证据核验。

交付精确的文件路径、实际格式、可编辑对象范围、讲稿/动画/媒体状态，以及影响使用的
少量限制。PPTX、可选 PDF/预览、讲稿和证据索引按用户所需提供，不强制全套附件。
再按需进入 [答辩演练](rehearsal.md)，以真实页面和讲稿提问；不自动替用户连续答完。
