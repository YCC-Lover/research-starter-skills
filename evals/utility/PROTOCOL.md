# 实用价值对照协议

本轮将原有“内容是否合格”检查升级为“成果是否有助于推进研究”的分级评价。以下规则、输入和技能指导在首次模型派发前固定，并记录对应 Git 提交。任务材料均为本项目编写的合成练习。

## 固定实验

- 六类任务，每类两次独立重复，共十二对、二十四个新上下文。每对为直接使用 Codex 与显式加载指定 skill；U01 可按总入口选择相关模块。
- 同一主会话继承的模型与推理设置，无模型覆盖。两组使用完全相同的任务、材料、可用工具和篇幅要求。执行者只收到用户请求和原始材料；检查项、事实索引和评分规则只发给判读者。
- U06 是两轮任务：先开始练习，再发送固定学生回答。第二轮沿用各自上下文；第一轮问题与第二轮反馈均保留。其他任务各一轮。
- 固定完成这二十四次任务后汇总，完整保留输出。发现问题时另列修正与新一轮验证，原轮不择优重跑。输入传输故障单列处理。
- 两组均可用只读计算工具，输入在消息中提供。加载组额外读取对应技能指导。所有任务的中间文件采用维护者D盘工作目录，科研输入和仓库保持原样。

## 五项分级评分

每题五个维度，各0至3分，满分15。具体表现由 [cases.json](cases.json) 的检查项与事实索引确定。评价研究推进、证据整合、交付可用、行动决策、协作效率，而非固定表头或句式。

| 分值 | 锚点 |
| --- | --- |
| 0 | 缺失该项交付，或有实质性事实/方向错误使其无法使用 |
| 1 | 泛化建议或局部处理；用户仍需自行完成关键整合、写作或决策 |
| 2 | 基本可用，有一个影响使用的具体缺口或需要小幅补充 |
| 3 | 具体、充分且与任务预算匹配，用户可以直接采用或据此继续 |

出现数值、证据版本或完成状态的实质错误时，证据整合维度计0，并单列错误及其影响。其他维度分别判断，保留多维结果。篇幅更长、表格更多或口吻自信本身不加分；替代的有效研究方案同样可获高分。

## 匿名与顺序检查

由两个独立判读上下文分别评价同一批答案，交换答案呈现顺序并重新分配匿名标签；判读者看不到加载状态、执行者身份、读取清单和另一轮分数。每项先给可定位的答复原句，再给分数与理由，同时指出用户仍需补做的具体工作。完整执行轨迹与精确服务端模型版本若未返回，按接口实际可见范围记录。

保留两份分数，主会话核对事实和直接引文。结果同时报告分维度得分、每对分差、重复间变化、交换顺序后判断一致程度，以及长度等可测描述。判读分歧按原样展示，复核意见另列。模型判读是本轮评价方式；人类使用体验可沿相同任务继续收集。

## 汇总规则

单份答复得分取两次判读的平均；每对总分差为加载组减直接组。差值大于0.5列为本轮加载较高，小于-0.5列为直接较高，其余列为接近。按任务和维度汇总，并列出有代表性的具体帮助、额外工作或无差异情形。这里的阈值是展示规则，样本量为十二对，不据此进行显著性推断或外推用户收益。

公开首页围绕可核对的成果与使用场景表达价值。实测案例链接到本轮原始答复，统计写明任务和评价方式，通用能力介绍与本轮观察分别呈现。

判读设计参考 [Zheng等，Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685) 对位置、冗长与自偏好的讨论；本轮采用匿名、顺序交换和逐项事实核对来检查这些影响。
