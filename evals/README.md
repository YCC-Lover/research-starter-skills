## 复杂任务怎样比较

本轮六类任务各执行两次独立重复，共十二对。篇幅与工具条件对齐，执行者只获得用户请求和原始材料。开题练习包含固定学生回答后的第二轮反馈。

评价五个维度：研究推进、证据整合、交付可用、行动决策、协作效率。每项0至3分，以具体事实和用户还需完成的工作为依据。两个匿名判读上下文交换答案顺序，分别保留原句、分数与理由。结果按任务、维度和重复次数呈现，方便观察适合自己的用法。

## 记录怎样核对

~~~text
python scripts/validate_behavior_eval.py
python scripts/validate_behavior_eval.py --impact
~~~

第一条核对来源快照、两组与重复完整性、连续引用、双份判读及平均分；第二条列出当前题目哪些输入或技能依赖发生变化。维护者可据此确定下一轮需要复测的任务。无关UI文案与任务依赖分别处理。

历史答复及失败继续保留。v1.3.1的[输入传输故障](runs/2026-10-20/TRANSPORT.md)单列记录，新上下文的正式结果按对应来源保存。工程测试使用确定性的解析器样本，模型实测使用实际运行的完整答复。

## 阅读结果时的上下文

本轮采用同一主会话继承的模型设置与独立判读上下文，精确后端版本、种子和完整工具轨迹按工具可见范围记录。分数反映十二对合成任务上的模型评价；人类研究者可以用相同材料继续核对可用性、练习体验和实际工作量。

新增模型运行由使用者选择并授权，安装和CI验证使用本地脚本。真实任务继续采用自己有权使用的材料、当前来源和项目要求。
